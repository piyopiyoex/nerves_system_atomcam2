# 文書案内

このディレクトリでは、現在の利用方法、長期的な設計判断、開発時の調査記録を
分けて管理します。

## 読む順序

1. [はじめに](はじめに.md): 初回のビルド、MicroSD への書き込み、接続確認
2. [構成](構成.md): 起動、更新、映像、状態画面、永続領域の全体像
3. [運用](運用.md): 日常の確認、映像操作、更新、復旧、任意機能

設計の理由を確認するときは [設計判断](adr/README.md)、過去の調査や実機検証を
追うときは [開発記録](worklog/README.md) を参照してください。

## 文書の優先順位

同じ内容が異なる文書に現れる場合は、次の順序で判断します。

1. 現行コード
2. `docs/` 直下の現行資料
3. `docs/adr/` の採用済み設計判断
4. `docs/worklog/` の当時の作業記録

`worklog/` には、後から解決した障害、採用しなかった案、途中段階の仕様も残します。
現在の操作方法を判断する根拠にはせず、経緯と再発時の調査材料として使用します。

## ディレクトリ

```text
docs/
├── README.md
├── はじめに.md
├── 構成.md
├── 運用.md
├── adr/
├── assets/
└── worklog/
```

- `adr/`: 長期間維持する設計判断
- `assets/`: 文書から参照する画像と図
- `worklog/`: 日付ごとの調査、実装、検証、提案の記録

## ファイル名

- 文書は日本語で記述する
- ファイル名は日本語で簡潔に表す
- ADR は `NNNN-判断内容.md` とする
- 作業記録は `YYYYMMDD-内容.md` とする
- コード識別子、コマンド、環境変数、通信方式の名称は原表記を維持する

## ADR の基本構成

```text
# ADR NNNN: 判断内容

## 状態
## 背景
## 決定
## 影響
## 関連資料
```

一つの ADR には一つの長期的な判断を記録します。実装手順や日々の試験結果は
`worklog/` に分離します。文書配置の判断は
[ADR 0010](adr/0010-文書の役割と配置を分離する.md) に記録しています。

## 作業記録の基本構成

```text
# YYYY-MM-DD 内容

## 文書情報
## 目的または背景
## 実施内容
## 結果
## 残件
## 関連資料
```

既存記録は情報を失わないことを優先しているため、本文の見出し構成には差があります。
すべての記録の先頭に、日付、種別、状態、現在の位置づけを記載します。
