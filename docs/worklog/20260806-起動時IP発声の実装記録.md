- 状態: 完了

起動発声「起動しました。」に続けて、本機の IP アドレスを 1 桁ずつ読み上げる
機能を追加する提案。発声内容は「(有線/無線)あいぴー(IP アドレスの
digit-by-digit 読み上げ、オクテット間は「ドット」)です。」形式(例:
eth0 が `192.168.1.77` の場合 →「ゆうせん あいぴー いち・きゅう・に
ドット いち・ろく・はち ドット いち ドット なな・なな です」)。
**eth0 と wlan0 が両方 IP を持つ場合は両方読み上げる**(有線・無線の
どちらの IP かが分からないと役に立たないため)。

## 背景

現在の起動発声(`package/atomcam2-boot-announce/`)は、ビープ 3 回 +
「起動しました。」を**ビルド時に 1 本の raw PCM(`boot-announce.raw`、
39,600 バイト、S16LE/8000Hz/mono)へ結合**し、`atomcam2-aoplay`
(IMP_AO を叩く自前 C バイナリ)で**1 回だけ再生**する設計になっている
(`docs/worklog/20260804-起動安定化と状態画面の作業記録.md` に記録済み、VERSION 1→2 で複数音声の結合を
採用)。IP アドレスは起動のたびに変わり得る動的な値なので、この静的な
1 ファイル方式では対応できない。

## 目的

固定音声(起動しました)に続けて、**動的な IP アドレス**を読み上げる。
DHCP で複数拠点の SSID を切り替える運用([[atomcam2-wired-lan]])が既に
あるため、「今どの IP で起動したか」を音声だけで確認できると、モニタ
なしでの導入時に有用。

## 発声仕様

- 語順: 「ゆうせん」または「むせん」→「あいぴー」→ 第1オクテット
  (1桁ずつ)→「ドット」→ 第2オクテット(1桁ずつ)→「ドット」→
  第3オクテット(1桁ずつ)→「ドット」→ 第4オクテット(1桁ずつ)→「です」
- **eth0(有線)と wlan0(無線)の両方に IP がある場合は、この文をそれぞれ
  1 回ずつ発声する**(有線を先、無線を後)。片方しか無い場合はそちらだけ。
- 例(eth0=`192.168.1.77`、wlan0=`192.168.91.77` の両方が有効な場合):
  1. ゆうせん / あいぴー / いち / きゅう / に / ドット / いち / ろく /
     はち / ドット / いち / ドット / なな / なな / です
  2. むせん / あいぴー / いち / きゅう / に / ドット / いち / ろく /
     はち / ドット / きゅう / いち / ドット / なな / なな / です
- 数字は 1 桁ずつ発声(「百九十二」のような桁読みはしない、ユーザ指定
  どおり)
- 必要な語彙: `ゆうせん` / `むせん` / `あいぴー` / `ぜろ`〜`きゅう`
  (10 個)/ `ドット` / `です` の**計 15 クリップ**で、任意の組み合わせを
  組み立てられる。

## 音声素材の作成方法(検証済み・実装で採用)

新規に人手録音するのではなく、**開発ワークステーション上で TTS 合成し、
実機と同じ PCM フォーマットへ変換する**方式を採用した。

当初は espeak-ng で試作したが、聞き取り確認の結果、既存の起動発声
「起動しました。」(`boot-announce.raw`)と声質が揃わないため不採用と
した。**同じ声(めいちゃん、`mei_normal.htsvoice`)で統一する**方針に
切り替え、ワークステーション上に既にセットアップ済みだった
[Open JTalk](https://open-jtalk.sourceforge.net/)(`~/nerves_examples/open_jtalk_elixir`
プロジェクトに vendored 済みの `open_jtalk-1.11` + Mei ボイス)を使って
合成した。

```sh
# 1. Open JTalk (Mei ボイス) で合成 (48kHz/16bit/mono WAV)
cd ~/nerves_examples/open_jtalk_elixir
unset MIX_TARGET; export OPENJTALK_FULL_STATIC=0
mix run -e 'OpenJTalk.to_wav_file("あいぴー", out: "/tmp/aipi.wav")'

# 2. 実機フォーマット(S16LE, 8000Hz, mono, ヘッダ無し raw)へ変換
ffmpeg -i /tmp/aipi.wav -ar 8000 -ac 1 -f s16le /tmp/aipi.raw
```

15 クリップ全体は `0.raw`〜`9.raw` / `ip.raw` / `dot.raw` / `desu.raw` /
`wired.raw` / `wireless.raw` の計 160KB 程度(既存の
`boot-announce.raw` 39.6KB より一クリップあたりは小さいが素材数が多い
ため合計はやや大きい)で収まった。

**入力は漢字ではなくひらがなで与えること**(検証で判明): 「有線」を
そのまま TTS に渡すと不自然な読み・長い間になったが、「ゆうせん」と
ひらがなで渡すと自然になった。「無線」/「むせん」でも同様。**すべての
クリップはひらがな入力で合成する**方針とした
(`あいぴー` / `ぜろ`〜`きゅう` / `ドット` / `です` / `ゆうせん` /
`むせん`)。

### 音量正規化(実装後に判明・追加対応)

Open JTalk 合成直後の raw クリップは、`ffmpeg volumedetect` で計測すると
mean ≈ -30dB / peak ≈ -13〜-19dB と、既存 `boot-announce.raw`
(mean -11dB / peak -0.4dB)よりかなり小さく、実機再生で「起動しました」
に比べて IP 発声が明らかに聞き取りにくい音量だった(実機検証で発覚)。

**原因**: 再生スクリプト(`atomcam2-boot-announce`)側のゲイン・音量
パラメータ(`ATOMCAM2_BOOT_ANNOUNCE_GAIN`/`_VOLUME`)は両方の発声で
共通のデフォルト値を使っており差はない。差は**音源そのものの振幅**
(TTS 合成結果 vs 既存の正規化済み録音)にあった。

**対応**: 15 クリップ全てを `ffmpeg` の `volume=<gain>dB` フィルタで
**ピーク -1dB 付近へ正規化**(クリップごとに `volumedetect` で
`max_volume` を測定し、`-1.0 - max_volume` を適用ゲインとして計算)。
正規化後は peak が全クリップで `boot-announce.raw` の peak(-0.4dB)と
同水準の -1.0dB に揃い、実機(192.168.1.77)で聞き比べて音量差が
解消したことを確認済み。この正規化は `atomcam2-boot-announce.mk` の
`ATOMCAM2_BOOT_ANNOUNCE_VERSION` を 5→6 に上げて反映した。

**教訓**: TTS で新規に合成した音声素材を既存の録音済み音声と混ぜて
再生する場合、フォーマット(サンプルレート/ビット深度)を揃えるだけ
でなく、**音量(ピークレベル)も明示的に揃える工程を組み込むこと**。
聞き取り確認をせずフォーマット一致だけで検証完了とすると見落とす。

## 実装方式

### 音声素材

`package/atomcam2-boot-announce/digits/` のような新規ディレクトリに、
15 個の小さな raw PCM ファイル(`0.raw`〜`9.raw`, `ip.raw`, `dot.raw`,
`desu.raw`, `wired.raw`, `wireless.raw`)をビルド時アセットとして
リポジトリに追加し、既存パッケージの `INSTALL_TARGET_CMDS` で
`/usr/share/atomcam2/digits/` へインストールする(`gc2053-t31.bin` を
`atomcam2-camera` パッケージへ追加したのと同じパターン)。

### ランタイム結合・再生

`Atomcam2NervesApp.BootAnnounce`(`boot_announce.ex`)を拡張する:

1. 既存の `System.cmd(@command, [])`(`boot-announce.raw` の再生)は
   **そのまま変更しない**(IP 未取得でも「起動しました」は必ず鳴る)。
2. 成功後、`ipv4_of("eth0")` と `ipv4_of("wlan0")`(`camera_native.ex`/
   `dashboard/collector.ex` に既にあるパターンを再利用)を**両方**取得し、
   非 `nil` のものそれぞれについて 1 文ずつ発声を組み立てる(有線が先、
   無線が後)。**両方 `nil` なら IP 発声は全体をスキップ**し、起動発声
   自体は失敗にしない。
3. インターフェースごとに、区切り語(`wired.raw`/`wireless.raw`)+
   `ip.raw` + IP の各桁 + `dot.raw` + `desu.raw` のクリップ列を組み立て、
   `File.read!/1` で読み込んだバイト列を**全インターフェース分まとめて
   1 個の一時 raw ファイル**(`/tmp/camd-ip-announce.raw`)へ連結して
   書き出す(`/tmp` は noexec だが**データファイルの読み書きは問題ない**、
   実行するのは別バイナリの `atomcam2-aoplay` 側)。
4. 既存の再生ラッパー `/usr/bin/atomcam2-boot-announce` を
   `ATOMCAM2_BOOT_ANNOUNCE_SOUND=/tmp/camd-ip-announce.raw`
   環境変数付きで**2 回目の呼び出し**として再実行する(オーディオ
   デバイス待機・フォールバックロード等のロジックを再利用でき、
   ゲイン/音量パラメータも固定発声と同じデフォルトが自動的に揃う)。

「起動しました」と「IP 発声」を 2 回の `aoplay` 呼び出しに分けるのは、
IP が起動直後(DHCP 未完了)にまだ確定していないケースでも固定発声だけは
必ず鳴らすため。IMP_AO の再オープンによる短い間隔が気になる場合は、
**両方の raw を 1 つのバッファに事前連結して 1 回の呼び出しにまとめる**
最適化も可能(フォーマットが完全一致しているため技術的には単純)。

## 非目標

- オンデバイスでの TTS 合成は行わない(素材は開発時に生成し、リポジトリに
  静的アセットとしてコミットする。実機側は連結して再生するだけ)。
- 桁読み以外の読み上げ方式(「百九十二」等)は対象外。
- IPv6 は対象外(本プロジェクトは IPv4 前提)。

## 検証計画

1. 15 クリップを espeak-ng(ひらがな入力)で生成し、聞き取りやすさを
   確認(必要ならボイス/話速調整、または人手録音に差し替え)。
2. `BootAnnounce` にクリップ連結・追加再生ロジックを実装。
3. **192.168.1.77**(eth0=`192.168.1.77`・wlan0=`192.168.91.77` の両方が
   稼働中)へ投入し、実機で「起動しました」→ 有線 IP → 無線 IP の順に
   発声することを確認する。両インターフェースが同時に有効な実機なので、
   1 回の検証で両方の発声を確認できる。
4. IP 未取得(片方または両方のインターフェースが起動直後で未接続)の
   ケースで、取得できた方だけ発声する/両方無ければ IP 発声が静かに
   スキップされることを確認(クラッシュ・リトライループにならないこと)。
5. 複数拠点(異なる eth0/wlan0 IP)で発声内容が正しく変わることを確認。

## 実施結果(追記)

上記の検証計画どおり実装・検証を完了した。

- `boot_announce.ex` に `announce_ip/0` 等を実装、`package/atomcam2-boot-announce/`
  に Open JTalk(Mei ボイス)で合成・音量正規化した 15 クリップを追加
  (`ATOMCAM2_BOOT_ANNOUNCE_VERSION` 3→6)。
- **192.168.1.77**(eth0/wlan0 両方稼働)へ投入し、「起動しました」→
  有線 IP → 無線 IP の順で発声することを確認。
- 音量正規化前は IP 発声が「起動しました」より明らかに小さく聞こえる
  問題が実機検証で発覚し、上記「音量正規化」の対応で解消。
- **192.168.31.31**(カナリヤ機)にも同ファームを投入し、起動発声が
  問題なく再生されることを確認(`boot-announce-history.log` に
  `ok on attempt 1` を記録)。

### IEx からの ON/OFF トグル(追加実装)

検証後、ユーザ要望により**起動時 IP 発声を IEx から切替可能**にした
(固定の「起動しました」チャイムはトグルの影響を受けず常に鳴る)。

- `Atomcam2NervesApp.BootAnnounce.ip_announce_enabled?/0` — 現在の設定
  を返す(既定 `true`)。
- `Atomcam2NervesApp.BootAnnounce.set_ip_announce/1` — `/media/mmc/ip-announce-enabled`
  (FAT パーティション)へ永続化。次回起動から反映。
- `Atomcam2NervesApp.BootAnnounce.announce_ip/0` を `defp` から `def` へ
  変更し、トグルの状態に関係なく IEx から即座にテスト再生できるように
  した。
- 192.168.1.77・192.168.31.31 の両機で、`false` 設定 → 再起動 →
  永続化確認(`ip_announce_enabled?/0` が `false` のまま)→
  `RingLogger.grep("announce")` で固定チャイムのみ再生されIP発声が
  スキップされたこと → `true` に戻して再起動、の一連を実機確認済み。
- 運用手順は [運用リファレンス §4.5](20260805-運用手順の整理.md) 参照。
