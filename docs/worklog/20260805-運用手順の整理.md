## 1. 接続

```bash
# SSH で IEx に入る(公開鍵認証)
ssh <ip>

# ダッシュボード(HTTP・ポート 80)
#   ブラウザで http://<ip>/
#   健全性チェック: http://<ip>/healthz  → ok
#   正規 API:      http://<ip>/status.json

# ホスト鍵が変わった(IP 使い回し)ときは古い鍵を消してから
ssh-keygen -R <ip>
```

### SSH ホスト鍵の更新(IP 使い回しで警告が出るとき)

別端末が同じ IP を使っていた等でホスト鍵が変わると、`ssh` /
`mix upload` が `REMOTE HOST IDENTIFICATION HAS CHANGED!` で止まる。
古い鍵を消し、必要なら新しい鍵を先に登録して非対話で進める。

```bash
# 古いホスト鍵を削除
ssh-keygen -R <ip>

# 新しいホスト鍵を known_hosts に事前登録(mix upload が対話待ちで
# 固まるのを防ぐ)
ssh-keyscan -t ed25519,rsa <ip> >> ~/.ssh/known_hosts

# もしくは初回接続を自動受理して繋ぐ
ssh -o StrictHostKeyChecking=accept-new <ip>
```

> `mix upload <ip>` がプログレスも出さず固まる場合、多くはこの
> ホスト鍵確認プロンプト待ち。上の `ssh-keygen -R` + `ssh-keyscan` を
> 先に済ませてから再実行する。

IP が分からないときは MAC で探す(§6 参照)。既知の MAC:
- 有線 eth0(USB Ethernet, RTL8152): `00:e0:4c:36:02:31`
- Wi-Fi wlan0: `7c:dd:e9:02:ea:65`

## 3. ダッシュボード(`Atomcam2NervesApp.Dashboard`)

```elixir
# 起動 / 停止(httpd ごと。OFF ならポートも閉じてコストゼロ。永続)
Atomcam2NervesApp.Dashboard.enable(true)
Atomcam2NervesApp.Dashboard.enable(false)

# 現在有効か
Atomcam2NervesApp.Dashboard.enabled?()              #=> true / false
```

### パスワード登録(操作系 POST の認証)

`GET`(状態表示・スナップショット)は匿名で見られるが、`POST /announce`
(テスト発声)と `POST /reboot`(再起動)は **HTTP Basic 認証が必須**。
ユーザー名は固定で `admin`、パスワードは IEx から登録する。

```elixir
# パスワードを登録(/data に 0600 で永続保存。SHA-256 で定数時間比較)
Atomcam2NervesApp.Dashboard.set_password("your-password")

# パスワードを削除(= 操作系を全面禁止。安全側の既定)
Atomcam2NervesApp.Dashboard.set_password(nil)
```

- **未登録の間は操作系 POST を常に 401 で拒否**する(既定で安全)。
- ブラウザは 401 の `WWW-Authenticate` を受けて認証ダイアログを出す。
  ユーザー `admin` + 登録したパスワードで発声・再起動が実行できる。

### 4.5 起動時 IP アドレス読み上げの ON/OFF

「起動しました」に続けて、有線/無線 IP を 1 桁ずつ読み上げる機能
(`Atomcam2NervesApp.BootAnnounce.announce_ip/0`、詳細は
[起動時 IP 発声 提案書](20260806-起動時IP発声の実装記録.md))。**既定は
有効**。

```elixir
# 現在の設定を確認
Atomcam2NervesApp.BootAnnounce.ip_announce_enabled?()   #=> true / false

# 無効化(FAT パーティションに永続化、次回起動から反映)
Atomcam2NervesApp.BootAnnounce.set_ip_announce(false)

# 有効化に戻す
Atomcam2NervesApp.BootAnnounce.set_ip_announce(true)

# 再起動を待たずに今すぐ読み上げさせる(トグルの状態とは独立、いつでも呼べる)
Atomcam2NervesApp.BootAnnounce.announce_ip()
```

- `set_ip_announce/1` はあくまで**起動時の自動読み上げ**を止めるだけで、
  固定の「起動しました」チャイムは常に鳴る。
- 永続化先は `/media/mmc/ip-announce-enabled`(他の設定と違い `/data`
  ではなく FAT パーティション。理由は §9 参照)。

## 6. IP が分からない端末を探す(ホスト PC 側、MAC 検索)

カメラの MAC は固定なので、**ping スイープで ARP を埋めてから MAC で照合**
すれば、IP が変わっても(ルータ変更・直結など)特定できる。

既知の MAC:
- eth0(USB Ethernet, RTL8152): `00:e0:4c:36:02:31`
- wlan0(Wi-Fi): `7c:dd:e9:02:ea:65`
- ※もう 1 台の eth0 は `00:e0:4c:36:02:48`(192.168.1.77 の個体)

```bash
# 1) 自分がどのサブネットに居るか確認(複数 NIC / VPN があると要注意)
ip -4 -o addr show | grep -v " lo "

# 2) 該当サブネットを ping スイープ(複数サブネットをまとめて叩いてもよい)
for i in $(seq 1 254); do
  ping -c1 -W1 192.168.1.$i  >/dev/null 2>&1 &
  ping -c1 -W1 192.168.31.$i >/dev/null 2>&1 &
done; wait

# 3) ARP 近傍テーブルを MAC で照合(dev 列で「どの NIC で見えたか」も分かる)
ip neigh | grep -i "00:e0:4c:36:02:31"     # eth0 を探す
ip neigh | grep -iE "00:e0:4c|7c:dd:e9"    # Realtek/Ingenic 系をまとめて
```

出力例: `192.168.31.31 dev enp0s31f6 lladdr 00:e0:4c:36:02:31 REACHABLE`
→ その端末は **192.168.31.31**、`enp0s31f6`(有線)で到達可能。
(同一個体が拠点移動で IP を変えることがある。MAC は不変なので
この照合が最も確実。開発用カナリヤ機は 2026-08-06 時点で 31.31)

> 注意(重要): **ARP/`ip neigh` は同一 L2 セグメントでしか解決しない**。
> VPN や多重 NIC 経由だと、RTSP(TCP)は繋がっても **RTP(UDP)が届かず
> 映像だけ来ない**ことがある。RTSP `SETUP` 応答の `destination=` が自分の
> 正しい IP になっているか確認する:
> ```bash
> printf 'SETUP rtsp://<ip>:8554/video0_unicast/track1 RTSP/1.0\r\nCSeq:1\r\nTransport: RTP/AVP;unicast;client_port=55000-55001\r\n\r\n' \
>   | nc <ip> 8554 | grep -i Transport
> ```
> `destination=` が別 NIC/別セグメントの IP なら、そのクライアントには UDP
> RTP が届かない(= VLC で音沙汰なし)。**直結や同一セグメントで再確認**する。

### VPN 越しに RTSP を見る(重要)

RTSP(TCP)は繋がり SDP も取れるのに **VLC で映像が来ない**場合、多くは
**RTP(UDP)の経路**。LIVE555 は接続元 IP を RTP の `destination` にする:

- **L2TP/IPSec**: クライアントにカメラ側サブネットの仮想 IP が割り当たるので
  `destination` が同一サブネットになり **UDP 映像が届く**。
- **IPSec 単体**: 実 IP(別サブネット)のままで戻り UDP が消失し、**制御は
  繋がるが映像だけ来ない**。

**最も簡単な回避は VLC で RTSP-over-TCP を強制**する。RTP を RTSP の TCP
コネクションに多重化するので、UDP 宛先問題を回避できる。

**方法A: このストリームだけ TCP(手早い)**
1. VLC の **メディア → ネットワークストリームを開く**
2. URL: `rtsp://<ip>:8554/video0_unicast`
3. 同じ画面の下 **「その他のオプション(詳細設定)を表示」**にチェック
4. 一番下の **「編集オプション」**欄に次を追記(URL の後ろにスペース区切りでも可):
   ```
   :rtsp-tcp
   ```
5. 再生

**方法B: VLC 全体で常に TCP(一度設定すれば以後不要)**
- 設定(All 表示)→ 入力/コーデック → デマルチプレクサー → RTP/RTSP →
  **「RTP over RTSP (TCP) を使用」**にチェック → VLC 再起動

**方法C: コマンドライン**
```
vlc --rtsp-tcp rtsp://<ip>:8554/video0_unicast
```

## 6.5 複数拠点 Wi-Fi の登録(自宅 / 会社)

自宅・会社など複数の AP を登録しておくと、VintageNet(wpa_supplicant)が
**電波の届く方に自動接続**する。登録方法は 2 通り:

**A. ビルド時 env var(OTA で運ばれる・推奨)**
```bash
export NERVES_WIFI_SSID='home-ssid'        NERVES_WIFI_PASSPHRASE='home-pass'
export NERVES_WIFI_SSID_2='office-ssid'    NERVES_WIFI_PASSPHRASE_2='office-pass'
# _3, _4 ... で拠点追加
mix firmware && mix upload <ip>
```
`WifiProvisioning` がコンパイル時にこれらを取り込み、`runtime.exs` が SD の
provisioning ファイルとマージする(**SD が優先=個体別上書き可**)。
**実 SSID/パスフレーズはソース・git に含まれない**(env var 由来)。

**B. SD の provisioning ファイル(個体別・OTA では更新されない)**
`/media/mmc/nerves-provisioning.conf`(FAT)に追記:
```
NERVES_WIFI_SSID=home-ssid
NERVES_WIFI_PASSPHRASE=home-pass
NERVES_WIFI_SSID_2=office-ssid
NERVES_WIFI_PASSPHRASE_2=office-pass
```
編集後は再起動で反映。**OTA(`mix upload`)はこのファイルを更新しない**ので、
OTA だけで拠点を増やしたいときは A(ビルド時 env var)を使う。

確認:
```elixir
VintageNet.get_configuration("wlan0")[:vintage_net_wifi][:networks]
|> Enum.map(& &1[:ssid])            #=> ["home-ssid", "office-ssid"]
VintageNet.get(["interface","wlan0","connection"])  #=> :internet なら接続済み
```

## 8. ファーム更新(OTA、ホスト PC 側)

```bash
# 例アプリのディレクトリで
cd examples/atomcam2_nerves_app
export MIX_TARGET=atomcam2 ATOMCAM2_SYSTEM_SOURCE=local

# アプリのみの変更なら firmware を直接ビルド(mix compile を先に走らせない)
mise exec -- mix firmware
mise exec -- mix upload <ip>
```

注意:
- **`mix compile` を単独で先に実行しない**。ローカルシステム(Buildroot)
  の再ビルドが誘発され、`ATOMCAM2_KERNEL_IMAGE`(検証済みカーネル、
  sha `b50658ea…`)の指定が必要になる。アプリ変更は `mix firmware` を
  直接叩くのが安全。
- 万一システム再ビルドになったら、検証済みカーネルを指す:
  ```bash
  ATOMCAM2_KERNEL_IMAGE=.../nerves_system_atomcam2-portable-0.3.0/images/uImage.lzma
  ```
  **SHA ピン(`scripts/post-image.sh` の `expected_kernel_sha256`)は
  絶対に変更しない**(Buildroot 版カーネルを焼くと SD 起動不能)。
- OTA(`mix upload`)は A/B rootfs のみ更新。Wi-Fi プロビジョニング
  (`/media/mmc/nerves-provisioning.conf`)や SSH 鍵は FAT パーティション
  にあり OTA では書き換わらない。

デバイス側でスロット確認:

```elixir
Nerves.Runtime.KV.get_all()          # 現在/候補スロット等
Nerves.Runtime.validate_firmware()   # 起動確認 OK を確定(自動検証構成なら不要)
Nerves.Runtime.reboot()
```

## 9. 設定ファイルと既定値

| 機能 | 永続ファイル | 既定(ファイル無し) |
| --- | --- | --- |
| ダッシュボード ON/OFF | `/data/atomcam2-dashboard/enabled.conf` | **ON** |
| ダッシュボード管理パスワード | `/data/atomcam2-dashboard/password.conf`(0600) | 未設定(操作系は 401) |
| OSD デバッグ表示 | `/data/atomcam2-native-camera/osd-debug.conf` | **ON** |
| native カメラ自動起動 | `/data/atomcam2-native-camera/auto-start.conf` | ON(`enabled=false` で無効) |
| 起動時 IP アドレス読み上げ | `/media/mmc/ip-announce-enabled` | **ON** |

いずれも **永続ファイルがあればそちらが優先**。既定値はコンパイル時
定数(ファイルが無い/読めない初期状態のときのみ適用)。IP 読み上げ
だけ `/data` ではなく `/media/mmc`(FAT)なのは、`BootAnnounce` が
起動シーケンスの早い段階(`/data` のファイルシステムチェックが終わる
前)で動くため、他の履歴ログ(`boot-announce-history.log`)と同じ
書き込み先を使っているから。
