## 結果の要約

- ホスト環境の問題(Hex の不整合、OTP バージョン不一致)を解消し、
  `mise exec` 経由でファームウェアをビルドできるようになった
- Wi-Fi SSID を変更したファームウェアを再ビルドし、MicroSD カードへ書き込んだ

- 動作確認したファームウェア: `atomcam2_nerves_app 0.3.0`
  (rootfs SHA-256 先頭 `3430e1a0`、fwup UUID `table-reason`)

## 1. ビルド環境の整備

### 問題 1: Hex アーカイブの Elixir バージョン不整合

`mix setup` が `Enum.__in__/2 is undefined` で失敗した。共有アーカイブ
ディレクトリの Hex が Elixir 1.20 向けにビルドされていたのが原因。

```sh
mix local.hex --force
mix archive.install hex nerves_bootstrap --force
```

### 問題 2: ホストとターゲットの OTP バージョン不一致

system v0.3.0 のターゲットは OTP 29 だが、シェルのデフォルトはグローバル
mise 設定の Elixir 1.19.4-otp-28 / Erlang 28.3 だったため、`mix firmware` が
Major version mismatch で失敗した。リポジトリの `.tool-versions`
(erlang 29 / elixir 1.20.2-otp-29)は非対話シェルでは自動適用されない。

対策: リポジトリ内では常に `mise exec -- mix ...` を使う。

## 2. ビルド手順(確定版)

```sh
cd examples/atomcam2_nerves_app
export MIX_TARGET=atomcam2
export MIX_ENV=prod
mise exec -- mix setup
mise exec -- mix firmware
```

system とツールチェーンはリリース済みアーティファクト
(`nerves_system_atomcam2-portable-0.3.0` / `nerves_toolchain_atomcam2-linux_x86_64-0.3.0`)
が GitHub Releases から取得されるため、Buildroot のフルビルドは不要。

成果物: `_build/atomcam2_prod/nerves/images/atomcam2_nerves_app.fw`(約 29MB)

## 3. Wi-Fi SSID の変更

release モードでは、`.fw` に取り込まれる `nerves-provisioning.conf` は
**アーティファクト側**のファイルが使われる。アプリビルド時の
`NERVES_WIFI_SSID` / `NERVES_WIFI_PASSPHRASE` 環境変数は反映されない
(これらは system をソースからビルドするときの post-image.sh でのみ使われる)。

SSID を変更する手順:

1. `~/.nerves/artifacts/nerves_system_atomcam2-portable-0.3.0/images/nerves-provisioning.conf`
   を編集する
2. `mise exec -- mix firmware` で再ビルドする
3. 検証: `unzip -p .../atomcam2_nerves_app.fw data/nerves-provisioning.conf`

書き込み済みカードの場合は、FAT パーティションの `nerves-provisioning.conf` を
直接編集するだけでもよい(再書き込み不要)。

## 4. MicroSD カードへの書き込み

> **重要:** このホストの `/dev/sda`(460GB)は **稼働中の AlmaLinux
> システムディスク**であり、fwup の検出候補に出てくるが絶対に選択しないこと。
> 書き込み先は接続した MicroSD カード(今回は `/dev/sdb`、29.1GB)。

```sh
lsblk                                 # カードのデバイス名と容量を確認
mise exec -- mix burn -d /dev/sdX    # X はカードのデバイス
```

書き込み後の検証:

```sh
scripts/atomcam2-check-sd-payload.sh /run/media/owner/ATOMCAM2
```

## 5. 実機での起動確認

### カード上の起動痕跡

カメラは起動時に FAT パーティションへ診断ファイル(`atomcam2-*.env`)を
書き込む。今回確認できた内容:

- `atomcam2-boot-manager.env`: スロット A を confirmed として選択、
  メタデータ正常
- `atomcam2-sbin-init.env`: スロット A の SquashFS をマウントして起動
- `atomcam2-pre-run.env`: `stage=pre_run_complete`、`/data` は ext2 として
  マウント済み(初回フォーマット成功)
- `atomcam2-wifi-driver.env`: atbm603x ドライバのロード成功、
  `wlan0_present=1`、factory MAC `7C:DD:E9:02:EA:65`
- `atomcam2-pivot-root.err` / `atomcam2-old-root-unmount.err`: 空(エラーなし)

補足: `atomcam2-network.env` はドライバロード直後(Erlang 起動前)の
スナップショットのため `wlan0_present=0` / IP なしでも異常ではない。

### 「起動しない」ように見えた原因

1. Nerves 起動中はベンダーのカメラ機能・LED 制御が動かない(デフォルト
   無効)ため、本体は無反応に見える
2. ホスト側で mDNS が未設定のため `nerves.local` を解決できない
   (avahi + firewalld の mdns 許可で恒久対応可能)
3. `known_hosts` に同 IP の古いホスト鍵が残っており SSH が拒否された
   (`ssh-keygen -R <IP>` で解消)

### SSH 接続の確認

```sh
ssh nerves@192.168.222.64   # ユーザー名 nerves を明示すること
```

接続すると motd に稼働中ファームウェアが表示され、ビルド成果物と一致する
ことを確認した:

```text
Nerves nerves atomcam2_nerves_app 0.3.0 (3430e1a0-53f1-5f3e-87c8-3b32c1ab4466) mipsel
```

## 6. カメラ互換機能の自動起動設定

手動での起動・停止(`atomcam2-vendor-camera start/stop`)を確認した後、
ターゲットの IEx で次を実行すると起動時に自動実行される:

```elixir
File.mkdir_p!("/data/atomcam2-vendor-camera")
File.write!("/data/atomcam2-vendor-camera/auto-start.conf", "enabled=true\n")
```

内容は正確に `enabled=true`(末尾改行 1 個まで許容)であること。無効化は
`enabled=false` の書き込みか、ファイルの削除。`/data` は永続領域のため、
この設定はファームウェア更新後も保持される。
