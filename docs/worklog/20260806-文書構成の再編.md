## 背景

`docs/` 直下に現行資料、提案書、技術相談、実装報告、引き継ぎ書が混在し、
途中段階の情報を現行仕様と誤認しやすい状態になっていた。特に旧 `docs/README.md` と
`architecture.md` は、完成したネイティブカメラ方式より前の構成を中心に説明していた。

## 実施内容

- `docs/` 直下の文書を 34 件から 4 件へ整理した
- 現行資料を `README.md`、`はじめに.md`、`構成.md`、`運用.md` に再構成した
- 長期的な判断を `docs/adr/` に集約し、一覧と ADR 0009、ADR 0010 を追加した
- 提案、調査、実装、検証、引き継ぎを `docs/worklog/` へ移動した
- 開発記録を `YYYYMMDD-内容.md` へ統一し、先頭へ文書情報を追加した
- 文書用画像を `docs/assets/` に集約し、現行構成図を更新した
- ルート README、変更履歴、サンプルアプリ README、コード内の文書参照を更新した

本文は、現行資料へ吸収した後も調査証跡として残した。原記録が途中で終わっていた一件は、
推測で補完せず「記録不完全」と明示した。

## 確認結果

- `docs/` 直下は 4 文書のみ
- すべての開発記録に日付、種別、状態、現行資料への案内がある
- すべての Markdown の局所リンクが解決できる
- すべての Markdown のコード囲みが対応している
- 構成図の SVG は妥当な XML として解析できる

Elixir の整形確認は、再編作業環境に `mix` がなかったため実行していない。
変更した Elixir と C の箇所は文書参照と説明文のみで、処理ロジックは変更していない。
