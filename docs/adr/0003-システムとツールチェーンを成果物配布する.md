# ADR 0003: システムとツールチェーンを Nerves 成果物として配布する

## 状態

2026 年 7 月 18 日に承認し、実装済み。

Nerves システムとツールチェーンを Nerves 成果物として GitHub Release から取得できる。
手動公開経路は検証済みで、公開作業の自動化は独立した改善事項とする。

## 背景

標準的な Nerves アプリケーションは通常、`mix deps.get` の実行時に、事前構築済みの
システム成果物とツールチェーン成果物を取得します。

Atom Cam 2 のシステムとツールチェーンは現在このリポジトリにあり、ローカルで
構築できます。サンプルアプリケーションはすでに公開済みのシステム成果物を解決しようと
しますが、想定する GitHub Release の成果物が存在しない場合はローカル構築へ
切り替わります。

この切り替えはシステム開発中には便利ですが、アプリケーション開発者の既定手順としては
不十分です。

- 新規環境でのアプリケーションビルドがローカルのシステムチェックアウトに依存する
- 開発者がローカルで準備したクロスツールチェーンを用意する必要がある
- システムに変更がなくても Buildroot が実行される
- クリーン環境および継続的統合でのビルドを再現しにくい
- 通常の独自 Nerves target と同じ方法でリポジトリを利用できない

システムとツールチェーンのプロジェクトは現在同じリポジトリに置かれ、連動する版を
使用しています。

## 決定

Atom Cam 2 のツールチェーンとシステムについて、版付きの事前構築済み成果物を
GitHub Releases から公開します。

標準的な Nerves 成果物の手順を使用します。

- `mix nerves.artifact` で成果物を構築する
- 各パッケージの `artifact_sites` に GitHub リポジトリを宣言する
- 標準の `v<version>` 形式でリリースタグを付ける
- Nerves が生成した正確なファイル名の成果物をアップロードする
- ツールチェーンまたはシステムのいずれかが欠けているリリースは未完了として扱う

両パッケージをこのリポジトリから公開する間は、システムとツールチェーンの版を
同期させます。両者のリリース周期を分ける必要が生じた場合は、版の関係を変更する前に、
リリース責任の分離または明示的な成果物タグ対応を決定する必要があります。

次の処理を行う自動リリース手順を追加します。

1. リポジトリの検査を実行する
2. ツールチェーン成果物を構築する
3. 指定したツールチェーンでシステム成果物を構築する
4. 成果物名と検査値を検証する
5. 対応する GitHub Release を作成または更新する
6. 両方の成果物をアップロードする
7. リリース完了とする前に、クリーン環境での取得とファームウェア構築を行う

サンプルアプリケーションは、既定で公開済み成果物を使用しなければなりません。

ローカルソースでの開発は、`NERVES_SYSTEM`、`NERVES_TOOLCHAIN`、または既存の
プロジェクト固有のソース上書き設定など、明示的な設定を使用する場合に限り対応します。
通常のアプリケーションビルドで、これらの上書き設定を必須にしてはなりません。

クリーン環境での検証は、次の要素が存在しない状態から開始します。

- ローカルチェックアウトの上書き設定
- 手動で選択したツールチェーン
- 以前に保存された Atom Cam 2 成果物
- 既存の Buildroot 出力ディレクトリ

当初はリポジトリ内のサンプルを検証用アプリケーションとして利用できます。ただし、
受け入れ試験では、独立して生成した Nerves アプリケーションが対象機器の依存関係を
利用できることも証明する必要があります。

## 影響

### 利点

- 他の Nerves target と同様に、`mix deps.get` でシステムとツールチェーンを取得できる
- アプリケーションのビルドで不要な Buildroot およびツールチェーンの構築を避けられる
- 継続的統合と導入時の手順を再現しやすくなる
- 成果物の検査値により、パッケージソースと取得した書庫の関係を引き続き保護できる
- 明示的に選択した場合は、ローカルでのシステム開発手順を引き続き利用できる

### 欠点

- リリースに 2 つの大きな生成成果物を含める必要がある
- ツールチェーンとシステムの版調整がリリース作業の一部になる
- リリース自動化を、ツールチェーンとシステムを構築可能な基盤で実行する必要がある
- Nerves の検査値対象となるソースを変更すると以前の成果物が無効になり、新しい
  リリースが必要になる

## 実装上の制約

- 生成した成果物の書庫をリポジトリへ登録しない
- クリーン環境の検証で、暗黙にローカルチェックアウトへ切り替えない
- 未登録のソースから構築した成果物をリリースしない
- システム構築時の既存の保護対象カーネル検証を維持する
- 開発用の上書き設定を明示的にし、文書化する
- アプリケーションの秘密情報やローカル環境設定を、実行履歴またはリリース成果物へ
  公開しない

## 受け入れ条件

- 版タグから、想定する両方の成果物が生成される
- GitHub Release に、Nerves が生成した正確なファイル名の両成果物が含まれる
- 新しいキャッシュからツールチェーンとシステムを 404 なしで取得できる
- `mix deps.get` がローカルのシステムビルドを起動しない
- 対象機器のローカル上書き設定なしで `mix compile` と `mix firmware` が成功する
- 生成したファームウェアが Atom Cam 2 で起動する
- サンプルアプリケーションの文書化された既定手順が公開済み成果物を使用する
- 別のクリーンな Nerves アプリケーションが、宣言した依存関係と target 設定だけで
  Atom Cam 2 を対象にできる
